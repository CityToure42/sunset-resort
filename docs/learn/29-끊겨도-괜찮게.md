# 29. 끊겨도 괜찮게 — 실시간이 안 될 때의 앱

폰은 지하철에서, 엘리베이터에서, 와이파이를 바꿀 때 자주 끊겨요. 실시간 기능이 앱 전체를 망치면 안 되니까
"끊겨도 혼자 놀기는 그대로"를 원칙으로 만들었어요.

## 세 가지 상황
| 상황 | 화면 | 동작 |
|---|---|---|
| 연결이 끊김 | 노란 배지 "연결이 끊겼어요 · 다시 연결 중", 인원 칩 숨김 | 혼자 걷기·석양멍·편지는 그대로. 1·2·4…30초 간격으로 다시 연결 |
| 다시 붙음 | 배지 사라지고 "지금 n명" 다시 | 내 상태를 다시 알리고, 접속 목록을 새로 받아 다시 그림(중복 없음) |
| 라이브러리 파일을 못 불러옴 | "함께 보기를 켤 수 없어요", 💬 버튼 없음 | 실시간만 꺼지고 나머지는 정상 |

## 끊기면 다른 사람을 왜 지울까?
끊긴 동안엔 다른 사람 소식을 못 받으니, 화면의 친구 캐릭터는 **멈춘 채 거짓말**을 하게 돼요.
그래서 끊기면 지우고, 다시 붙을 때 받은 최신 목록으로 다시 그려요. 같은 사람이 둘로 보이는 일도 없어요.

## 테스트에서 배운 것: 가짜도 진짜처럼
처음엔 다시 붙은 A가 B를 못 봤어요. 진짜 Supabase는 채널에 들어오면 **지금 있는 사람 목록 전체**를 주는데,
테스트용 가짜 연결은 그걸 흉내 내지 못했거든요. 그래서 가짜도 들어올 때 "hello"를 보내고, 받은 사람이 자기 상태를
답장하게 고쳤어요. **가짜가 진짜와 다르게 동작하면 테스트가 거짓말을 해요.** B단계 때 오류 코드(400 vs 500)에서 배운 것과 같은 교훈이에요.

## "못 불러옴"이 진짜 막히는지 확인
라이브러리 파일 요청을 일부러 막고(`route.abort`) 앱을 열어요.
- 앱이 정상으로 열리고 걸을 수 있는지
- 배지가 뜨고 💬 버튼은 없는지
- 실시간 서버로 요청이 하나도 나가지 않는지
그리고 "못 불러옴 검사" 한 줄을 일부러 지워 보니 테스트가 실패했어요 — 테스트가 진짜 그 줄을 지키고 있다는 증거예요.
