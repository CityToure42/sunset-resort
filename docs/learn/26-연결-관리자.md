# 26. 연결 관리자 — 끊겨도 알아서 다시 붙기

실시간 연결은 지하철, 와이파이 전환, 화면 꺼짐 때문에 자주 끊겨요.
`createRealtime`(src/net/realtime.js)이 이 모든 걸 한곳에서 맡아요.

## 하는 일
1. **연결하기·다시 연결하기** — 끊기면 1초, 2초, 4초, 8초, 16초, 30초 뒤에 다시 시도하고, 그 뒤로는 30초마다.
   간격을 점점 늘리는 걸 "지수 백오프"라고 해요. 서버가 아플 때 모두가 1초마다 두드리면 더 아프니까요.
   다시 붙으면 간격은 처음(1초)으로 돌아가고, 내 상태(닉네임·꾸미기·위치)를 다시 알려요.
2. **내 상태 올리기** — `setState`는 정해 둔 7칸(sid·닉네임·꾸미기·x·z·방향·모드)만 골라 보내요.
   폰에 저장된 기기 열쇠가 실수로라도 실리지 않게 하는 장치예요. 일부러 이 장치를 빼 봤더니 테스트가 바로 실패했어요.
3. **보내기 횟수 지키기** — 위치 0.5초, 채팅 2초. 10초 동안 아무것도 안 보냈으면 "아직 있어요(here)".
4. **받은 것 거르기** — 25번 문서의 검사 + 내 것 버리기 + 접속 목록에 없는 사람 것 버리기 + 폭주 무시.

## 어댑터(adapter)라는 생각
연결 관리자는 **"어떻게" 연결하는지는 몰라요.** 정해진 모양(connect·track·send·disconnect)만 알아요.
- 진짜 어댑터 `supabaseTransport`: Supabase 라이브러리로 진짜 서버에 붙어요.
- 가짜 어댑터 `fakeTransport`: 같은 브라우저의 창끼리 `BroadcastChannel`(브라우저에 들어 있는 창 사이 우편함)로 이어요.

덕분에 테스트에서는 진짜 서버 없이 창 두 개로 "서로 보이나"를 시험할 수 있어요.
콘센트 모양만 맞으면 어떤 전기제품이든 꽂히는 것과 같아요.

## 라이브러리를 읽다가 발견한 것
Supabase 라이브러리의 `send()`는 연결이 없을 때 **조용히 다른 방식(일반 웹 요청)으로 바꿔 보내요.**
그러면 "끊겼다"는 걸 우리가 알 수 없어서, 진짜 어댑터는 연결됐을 때만 보내도록 했어요.

## 시계를 바꿔 끼우는 테스트
재연결 테스트를 진짜로 하면 1+2+4+8+16+30초를 기다려야 해요.
그래서 `now`, `setTimer`를 바깥에서 넣을 수 있게 하고, 테스트에서는 "시간을 1000ms 앞으로 감기" 하는 가짜 시계를 넣었어요.
