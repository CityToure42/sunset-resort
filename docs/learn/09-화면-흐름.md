# 09. 화면 흐름 — 진입 화면, HUD, 그리고 모드

- `src/app.js` — 이제 조립은 `main.js`가 아니라 여기서 합니다. `createApp()`은 저장된 프로필을 읽어(`hydrateProfile`) 닉네임이 있으면 바로 해변으로, 없으면 진입 화면을 띄웁니다. 앱의 "모드"(`move`/`play`/`zen`/`messages`/`photo`)는 `setMode()` 한 곳에서만 바뀌고, 바뀔 때 `document.body.dataset.mode`에 적어둡니다. CSS와 테스트가 이 값 하나를 보고 동작합니다. `hooks`와 `frame` 배열은 다음 작업들(놀기 바, 석양멍, 유리병)이 자기 코드를 끼워 넣는 자리입니다.
- `src/ui/entry.js` — 진입 화면. 닉네임 칸에는 추천이 미리 채워져 있고 지우고 써도 됩니다. "해변으로 가기"를 누르면 `validateNickname`의 결과에 따라 `'length'`→"2~10자로 적어주세요", `'chars'`→"한글·영문·숫자만 쓸 수 있어요"를 보여주거나, 통과하면 프로필을 저장하고 해변으로 넘어갑니다. 꾸미기 컨트롤(`renderLookControls`)은 따로 떼어 두어 나중에 "꾸미기" 패널에서도 그대로 씁니다.
- `src/ui/hud.js` — 상단 칩(닉네임·꾸미기 버튼), 배지(오늘의 칵테일, 석양 이벤트), 우측 버튼(유리병 편지 쓰기, 바다로 가기), 하단 탭 5개. HUD는 "그리기"만 하고 무슨 일을 할지는 `onTab`, `onCustomize` 같은 콜백으로 app.js에 되돌려 줍니다. 이렇게 UI와 로직을 분리하면 테스트가 쉽고, 디자인을 바꿔도 로직은 안 건드려도 됩니다.
- `tests/e2e/helpers.mjs` — 대부분의 테스트는 진입 화면을 건너뛰고 싶어서, 페이지를 열기 전에 저장소에 프로필을 미리 넣어 줍니다(`seedProfile`). 실제 사용자가 두 번째 방문했을 때와 같은 상태입니다.
