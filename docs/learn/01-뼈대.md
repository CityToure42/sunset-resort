# 01. 뼈대 — 앱이 켜지기까지

이 단계에서 만든 것은 "빈 해변"도 아니고 그냥 파란 상자 하나가 도는 화면입니다. 하지만 앱의 가장 중요한 배관이 여기 다 들어 있습니다.

- `index.html` — 브라우저가 가장 먼저 여는 파일. 3D를 그릴 `<canvas id="c">` 한 장과, 나중에 UI를 끼워 넣을 빈 상자들(`#entry`, `#hud`, `#panels`…)이 있습니다. 맨 아래 `<script type="module" src="./src/main.js">`가 "이제 자바스크립트 시작"이라는 뜻입니다.
- `importmap` — 코드에서 `import ... from 'three'`라고 쓰면 실제로는 `vendor/three/three.module.js`를 읽으라는 안내문. 그래서 인터넷(CDN) 없이도 똑같이 돕니다.
- `styles.css` — 색과 배치 규칙. `:root`의 `--bg`, `--accent` 같은 값이 앱 전체 색의 "원본"이라 여기만 바꾸면 전부 바뀝니다. 캔버스는 `position: fixed; inset: 0`으로 화면 전체를 덮습니다.
- `src/scene/renderer.js` — three.js의 렌더러(그림을 그리는 엔진)를 만듭니다. WebGL이 없으면 `null`을 돌려주고, `main.js`는 그때 "이 브라우저에서는 3D를 켤 수 없어요"를 보여줍니다. `countPaintedPixels`와 `samplePixel`은 사람 대신 테스트가 화면을 "보는" 눈입니다.
- `src/main.js` — 출발점. 렌더러 → 장면(scene) → 카메라 → 매 프레임 그리기(`setAnimationLoop`). `window.__app`에 테스트가 읽을 값을 올려둡니다.
- `tests/e2e/smoke.spec.mjs` — "페이지가 뜨나, 그림이 그려지나, 크기를 따라가나, WebGL 없을 때 안내가 나오나"를 자동으로 확인합니다. 이 테스트를 먼저 써서 실패를 본 다음 코드를 짰습니다.

용어 한 줄: **scene**은 무대, **camera**는 관객의 눈, **renderer**는 무대를 사진으로 찍어 캔버스에 붙이는 사람입니다.
