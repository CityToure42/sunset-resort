# 25. 믿지 않고 검사하기 — 남이 보낸 메시지 다루는 법

실시간에서는 **다른 사람의 폰이 보낸 글**이 내 화면에 바로 쓰여요.
대부분은 우리 앱이 보낸 정상 메시지지만, 누군가 앱을 고쳐서 이상한 값을 보낼 수도 있어요.
그래서 받은 건 **한 번도 믿지 않고** 검사해요(`src/net/realtime.js`).

## 검사 규칙
| 받은 것 | 검사 |
|---|---|
| 일회용 번호(sid) | UUID 모양만 통과 (`isSid`) |
| 위치 x·z·방향 | 진짜 숫자인지(NaN·Infinity·"1" 같은 글자 거부), 해변 밖이면 안쪽으로 당김 |
| 동작 이름 | 정해 둔 6개(인사·건배·춤·눕기·비치볼·마시기)만 |
| 채팅 | 앞뒤 공백 빼고 30글자까지, 빈 글은 버림 |
| 닉네임 | A단계 규칙(2~10자, 한글·영문·숫자) 아니면 "손님" |
| 꾸미기 | 없는 모자·셔츠 번호는 기본값으로 |

**새 객체로 옮겨 담기**가 핵심이에요. 받은 객체를 그대로 쓰지 않고, 필요한 칸만 골라 새로 만들어요.
그러면 상대가 `token` 같은 엉뚱한 칸을 붙여 보내도 우리 쪽으로 따라 들어오지 않아요.

### `__proto__`라는 함정
동작 이름이 목록에 있는지 볼 때 `name in EMOTES`라고 쓰면, `'toString'`이나 `'__proto__'`도 "있다"고 나와요.
자바스크립트 객체는 이런 이름을 원래 갖고 있거든요. 그래서 `hasOwnProperty`로 **직접 넣어 둔 이름만** 인정해요.

## 보내는 횟수 제한 (`createLimiter`)
"마지막으로 보낸 시각"만 기억해서, 정해 둔 간격(위치 0.5초, 채팅 2초)이 지났을 때만 "보내도 돼"라고 답해요.
사용량(메시지 수)을 지키는 장치예요.

## 폭주 무시 (`createFloodGuard`)
한 사람에게서 1초에 20개 넘게 오면 그 사람 메시지를 3초 동안 무시해요.
고장 난 앱이나 장난 때문에 내 폰이 느려지는 걸 막아요. 다른 사람 메시지는 영향을 받지 않아요.

## 시간을 인자로 받는 이유
`ready(now)`, `allow(sid, now)`처럼 지금 시각을 **바깥에서 넣어 주면**, 테스트에서 "0.499초 뒤", "3초 뒤"를
실제로 기다리지 않고 숫자만 바꿔 바로 확인할 수 있어요. 테스트 10개가 1초도 안 걸려요.
