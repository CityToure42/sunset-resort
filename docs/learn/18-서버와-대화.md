# 18. 서버와 대화하기 — fetch 하나로

- `src/net/config.js` — 서버 주소와 공개 키(publishable). Supabase가 "공개해도 안전"하다고 명시한 키라 깃허브에 올라가도 괜찮습니다. 모든 권한을 가진 비밀 키는 어디에도 넣지 않아요. 앱이 할 수 있는 일은 17번에서 연 창구 함수 7개뿐이기 때문입니다.
- `src/net/api.js` — `createApi()`가 창구 함수 7개를 부르는 함수를 돌려줍니다. 하는 일은 단순해요: `주소/rest/v1/rpc/함수이름`에 `POST`로 `{p_token: …}` 같은 JSON을 보내고, 받은 JSON을 그대로 돌려줍니다. Supabase 공식 라이브러리를 쓰지 않은 이유는 지금 필요한 게 이것뿐이라서예요(실시간 기능이 필요한 C단계에서 넣습니다).
- **실패를 이유별로 나누기**: 앱 화면은 실패 이유에 따라 다른 말을 해야 해서 `ApiError.kind`로 나눕니다.
  - `offline` — 요청 자체가 안 나감(인터넷 없음)
  - `timeout` — 8초 안에 답이 없음(`AbortController`로 끊음)
  - `server` — 키 문제(401·403)나 서버 문제(5xx)
  - `notfound` — 없는/숨겨진 병(서버가 `P0002`)
  - `invalid` — 규칙 위반(글자 수 등, 400)
  처음엔 본문의 오류 코드를 상태 번호보다 먼저 봐서, 서버 오류를 "규칙 위반"으로 잘못 분류하는 버그가 있었고 테스트가 잡아냈습니다.
- 테스트(`tests/unit/api.test.js`)는 진짜 서버 대신 "가짜 fetch"를 넣어서 요청 주소·헤더·본문 모양과 실패 분류를 확인합니다.
