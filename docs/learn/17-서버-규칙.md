# 17. 서버 규칙 — 표는 잠그고, 창구만 연다

`supabase/migrations/001_b_stage.sql` 한 파일이 B단계 서버 전부입니다. Supabase 웹 화면의 SQL 편집기에 통째로 붙여 넣어 실행하면 되고, 여러 번 실행해도 안전하게(`if not exists`, `create or replace`) 썼습니다.

- **표 4개**: `bottles`(병), `replies`(답글), `likes`(누가 좋아요 했는지), `reports`(누가 신고했는지). 닉네임 2~10자, 내용 1~50자, 모양 6종, 위치 범위 같은 규칙을 표 자체에 `check`로 걸어서, 누가 앱을 거치지 않고 요청을 보내도 이상한 값은 저장되지 않습니다.
- **잠그기(RLS)**: 네 표 모두 "행 수준 보안"을 켜고 정책을 하나도 만들지 않았어요. 그러면 앱이 쓰는 익명 권한(`anon`)은 표를 아예 읽지도 쓰지도 못합니다.
- **창구 함수 7개**: 대신 `list_bottles`, `get_bottle`, `create_bottle`, `add_reply`, `like_bottle`, `report_bottle`, `my_bottles`만 열어 줍니다. 이 함수들은 `security definer`(만든 사람 권한으로 실행)라서 잠긴 표를 대신 다룰 수 있고, 돌려주는 값에 다른 사람의 토큰(비밀 열쇠)은 절대 넣지 않습니다. 모든 결과는 JSON(`jsonb`)이라 앱에서 바로 씁니다.
- **좋아요·신고 한 번만**: `likes`/`reports` 표의 기본키가 (병, 폰 토큰) 한 쌍이라, 같은 폰이 두 번 넣으려 하면 `on conflict do nothing`으로 무시됩니다. 실제로 새 줄이 들어갔을 때만 숫자를 1 올려요. 신고가 3이 되면 그 병은 목록에서 빠지고, 주인에게만 보입니다. 자기 병 신고는 세지 않아요.

**테스트**: `npm run test:sql`이 제 작업 환경의 진짜 PostgreSQL을 임시로 띄워 Supabase처럼 `anon` 역할을 만들고, 이 파일을 두 번 실행한 뒤 `tests/sql/b_stage_test.sql`의 검사 11개를 `anon` 권한으로 돌립니다. 처음에 1글자 닉네임이 통과하는 문제가 있었는데, 원인은 테스트용 데이터베이스가 글자 대신 바이트 수로 세는 설정이었기 때문이에요(Supabase처럼 UTF-8로 고침). 테스트가 진짜 실수를 잡는지 보려고 일부러 규칙 두 개를 망가뜨려 봤고, 둘 다 테스트가 잡아냈습니다.
