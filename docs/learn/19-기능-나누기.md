# 19. 기능 나누기 — app.js 다이어트

A단계가 끝났을 때 `src/app.js`는 400줄이 넘었어요. 놀기·석양멍·칵테일·편지·사진·품질 조정이 한 파일에 다 있으니, 편지 기능을 고치려면 상관없는 코드까지 같이 읽어야 했습니다.

그래서 B단계에서 가장 많이 바뀔 **유리병 편지** 부분을 `src/features/bottles.js`로 떼어냈어요. 코드는 한 글자도 바꾸지 않고 옮기기만 했고(그래서 "리팩터링"이라고 부릅니다), app.js에서는 이 한 줄만 부릅니다.

```js
setupBottles(app, { scene, camera, player, cameraRig, els, profile, saveProfile, getHud: () => hud, setMode, showToast });
```

필요한 재료(장면·카메라·플레이어·저장 함수 등)를 인자로 넘겨주고, 편지 기능은 `app.hooks`(모드가 바뀔 때)와 `app.frame`(매 프레임)에 스스로 끼어듭니다. 동작이 그대로인지는 옮기기 전과 후에 브라우저 테스트 61개를 똑같이 돌려서 확인했어요. 이제 B단계의 서버 작업은 대부분 이 파일 안에서 일어납니다.

`hud`만 `getHud: () => hud`처럼 함수로 넘긴 이유: HUD는 해변에 들어갈 때(닉네임을 정한 뒤) 만들어지기 때문에, 편지 기능을 준비하는 시점에는 아직 없을 수 있어서 "필요할 때 꺼내 쓰는" 방식으로 넘겼습니다.
