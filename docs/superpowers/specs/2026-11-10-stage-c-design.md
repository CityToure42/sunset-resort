# Sunset Resort C단계 — 같은 해변에서 만나기 (설계 문서)

작성일: 2026-11-10 · 상태: 사용자 검토 대기 · 선행: `2026-11-06-stage-b-design.md`(B단계 완료·배포됨, 커밋 b29ffb0)

## 1. 목표와 범위

- 같은 주소로 들어온 사람들이 **한 해변에서 서로의 캐릭터를 실시간으로** 본다(걷기·동작·석양멍).
- 머리 위 **자유 채팅 말풍선**(30자, 5초, 저장 안 함)으로 짧게 말할 수 있다.
- 상단에 "지금 n명이 함께 있어요"(나 포함).
- 사용자 결정(2026-11-09~10 대화):
  - 해변은 하나만 둔다. 누구나 들어온다.
  - 대화는 자유 채팅 말풍선으로 한다.
  - 소식 없는 캐릭터는 30초 뒤 지운다.
  - 만드는 방법은 Supabase 공식 라이브러리로 한다.
- 범위 밖:
  - 해변 나누기(30명 넘을 때)
  - 채팅 기록 저장
  - 귓속말
  - 차단·신고
  - 석양 이벤트 모임 연출
  - 캐릭터 충돌
  - 로그인

## 2. 화면 동작

### 2.1 다른 사람 캐릭터
- 각자의 꾸미기(모자·선글라스·셔츠·칵테일) 그대로 같은 휴양객 아바타로 그린다. 머리 위에 닉네임표(캔버스로 그린 글자 스프라이트)를 단다. 내 캐릭터에는 닉네임표를 달지 않는다.
- 위치는 받은 목표점으로 부드럽게 따라간다(보간). 움직이는 동안 걷기 동작, 멈추면 대기 동작.
- 동작은 받은 즉시 재생한다. 대상은 인사·건배·춤·눕기·비치볼·마시기이고, 하트·공 이펙트도 같이 나온다.
- 석양멍 중인 사람은 선베드 자리에 앉은 자세로 보인다. 여럿이면 겹쳐도 된다.
- 캐릭터끼리 충돌하지 않는다.
- 사진에는 함께 찍힌다.
- 동시에 그리는 수는 최대 30명이다. 넘으면 내 위치에서 가까운 30명만 그린다.

### 2.2 인원 표시
- 접속 상태 목록의 인원(나 포함)을 `#chip-people`에 "지금 n명이 함께 있어요"로 표시한다. 연결 전이나 끊겼을 때는 숨긴다.

### 2.3 채팅 말풍선
- 탭 바 위에 💬 버튼을 둔다(이동하기·놀기 모드에서 보임). 누르면 한 줄 입력칸(최대 30자)과 "보내기"가 나온다. Enter로도 보낸다.
- 보내면 내 캐릭터 머리 위에 말풍선이 5초 뜬다. 같은 순간 해변에 있는 사람도 그 캐릭터 머리 위에서 본다.
- 앞뒤 공백을 빼고 1~30자만 보낸다. 2초에 1번까지 보낼 수 있다.
- 말풍선은 캔버스에 글자로 그려서 HTML로 해석될 일이 없다. 입력칸 오류 문구는 textContent로 넣는다.
- 저장하지 않으므로 나중에 들어온 사람은 볼 수 없다.

### 2.4 들어오고 나가기
- 해변에 들어가면(enter 훅) 자동으로 연결한다.
- 앱이 숨겨지면(`visibilitychange` hidden, `pagehide`) 바로 채널에서 나간다. 다시 보이면 다시 들어온다.
- 끊기면 상단에 "연결이 끊겼어요 · 다시 연결 중" 배지를 띄운다. 혼자 노는 기능은 그대로 된다.
- 30초 넘게 아무 메시지도 오지 않은 캐릭터는 지운다. 접속 상태에서 나간(leave) 사람은 바로 지운다.

## 3. 실시간 구조 (Supabase Realtime, 무료 플랜)

### 3.1 확인한 사실(2026-11-09, 공식 문서)
- 무료 플랜 한도:
  - 동시 접속 200
  - 초당 메시지 100
  - 초당 Presence 메시지 20
  - 월 메시지 200만
- 과금 방식: Broadcast는 받는 사람마다 1건이고 보낸 사람은 세지 않는다. 월 한도를 넘으면 이메일 알림과 유예 기간이 있다.
- Realtime Settings의 "Allow public access"가 켜져 있으면 공개 채널을 쓸 수 있다.
- 공개(publishable) 키만으로 접속되는지는 문서에 명시가 없다. 구현 첫 작업에서 실서버로 확인한다. 안 되면 계획 단계에서 다시 정한다.

### 3.2 채널과 신원
- 공개 채널 `beach` 하나를 쓴다.
- **실시간 신원은 앱을 열 때마다 새로 만드는 일회용 번호(`sid`, UUID)** 로 한다. Presence key도 `sid`이다.
- B단계 기기 열쇠(`profile.token`)는 내 편지 조회 권한이므로 **실시간 메시지 어디에도 넣지 않는다.**

### 3.3 주고받는 내용

| 종류 | 내용 | 보내는 때 |
|---|---|---|
| Presence track | `{ sid, nick, look, x, z, ry, mode }` (mode: move·play·zen) | 들어올 때, 꾸미기·모드·닉네임이 바뀔 때 |
| Broadcast `move` | `{ sid, x, z, ry }` | 실제로 움직였을 때만(5cm 이상 이동 또는 0.1rad 이상 회전), 초당 최대 2번, 멈추면 마지막 위치 1번 |
| Broadcast `emote` | `{ sid, name }` | 동작할 때 1번 |
| Broadcast `chat` | `{ sid, text }` | 보낼 때, 2초에 1번까지 |
| Broadcast `here` | `{ sid }` | 10초 동안 아무것도 보내지 않았을 때 |

- 받는 쪽 검사(모두 순수 함수, 단위 테스트):
  - `sid`는 UUID 모양이어야 한다.
  - 숫자는 유한해야 하고, 위치는 해변 범위(`clampToBeach`)로 당긴다.
  - 동작은 `EMOTES` 키만 받는다.
  - 닉네임은 A단계 규칙(`validateNickname`: 2~10자, 한글·영문·숫자)으로 다시 검사한다. 통과 못 하면 "손님"으로 표시한다.
  - `look`은 `normalizeLook`으로 정리한다.
  - 채팅은 trim 후 앞 30자만 쓰고, 빈 글은 버린다.
  - 같은 `sid`에서 1초에 20건을 넘으면 그 `sid`의 메시지를 3초 무시한다.
  - 내 `sid`에서 온 것은 무시한다.
- Presence에 아직 없는 `sid`의 `move`·`emote`·`chat`은 무시한다(접속 상태가 먼저 와야 캐릭터가 생긴다).

### 3.4 사용량 추정(추측 포함)
- 친구 5명, 하루 1시간, 걷는 시간 30%: 월 약 130만 건(위치 위주)으로 한도 200만 안이다.
- 10명이면 넘을 수 있다. 넘을 때 대응(위치 초당 1번 등)은 그때 정한다.

## 4. 앱 코드

- 라이브러리: `@supabase/supabase-js`의 브라우저용 파일을 `vendor/supabase/`에 복사해 버전을 고정한다(three.js와 같은 방식, 정확한 버전과 파일은 계획에서 확인). 실시간에만 쓰고, B단계 `src/net/api.js`(fetch 직접 호출)는 그대로 둔다.
- 새 파일:
  - `src/net/realtime.js`
    - 연결 어댑터를 둔다. 진짜는 supabase-js 채널, 테스트용은 가짜.
    - 보내기 제한기(위치 0.5초, 채팅 2초, here 10초)를 둔다.
    - 받은 메시지 검사(`parseMove`·`parseEmote`·`parseChat`·`parsePresence`)를 둔다.
    - 상태(`connecting`·`online`·`offline`)를 알린다.
  - `src/features/people.js`: 다른 사람 목록(sid → 아바타·애니메이션·목표 위치·마지막 소식 시각), 보간, 30초 정리, 가까운 30명 그리기, 인원 칩, 끊김 배지, 내 상태 보내기(프레임마다 위치 검사, 모드·꾸미기 변경 훅).
  - `src/scene/labels.js`: 닉네임표·말풍선 스프라이트(캔버스 글자, 텍스처 해제 포함).
  - `src/ui/chat.js`: 💬 버튼·입력칸·보내기·오류 문구.
- 고치는 파일:
  - `src/app.js`: `setupPeople(app, …)` 한 줄과 필요한 훅만 추가한다(300줄 넘으면 빼낼 수 있는 부분을 함께 정리).
  - `src/ui/hud.js`: 끊김 배지 `setLinkState`.
  - `index.html`: 라이브러리 script.
  - `styles.css`.
- 테스트 노출: `window.__app.people`(목록·수), `__app.realtime`(상태, 테스트용 연결 주입). 테스트용 연결은 같은 출처의 `BroadcastChannel`로 브라우저 창끼리 메시지를 주고받는 가짜를 쓴다(Presence 흉내 포함).

## 5. 오류 처리

- **연결 실패·끊김:** 배지를 띄우고 다시 연결한다(1·2·4·8·16·30초, 이후 30초마다). 다시 연결되면 내 Presence를 다시 track하고, 받은 목록으로 사람들을 다시 맞춘다(없어진 사람 지우기, 새 사람 추가).
- **라이브러리 로드 실패:** 실시간만 끄고(배지 "함께 보기를 켤 수 없어요") 나머지는 정상 동작한다.
- **이상한 메시지:** 조용히 버린다. 폭주한 `sid`는 3초 무시한다.
- **채팅 전송 실패:** 입력칸에 "보내지 못했어요"를 띄우고 글은 남긴다.
- **성능:** 다른 캐릭터는 그림자를 끈 저품질 설정을 쓰고, 30명까지만 그린다. 자동 품질 조정이 low면 닉네임표만 남기고 이펙트를 생략한다.

## 6. 테스트

- 단위(Node):
  - 메시지 검사: 범위 밖 위치, NaN, 모르는 동작, 31자 이상, 빈 글, 이상한 sid, 이상한 look·닉네임
  - 보내기 제한기(가짜 시계)
  - 보간
  - 30초 정리
  - 가까운 30명
  - 폭주 무시
- 브라우저(Playwright, 가짜 연결로 같은 브라우저의 페이지 두 개):
  - A가 걸으면 B 화면의 A 캐릭터가 따라온다.
  - 닉네임표와 꾸미기가 맞다.
  - 건배가 재생된다.
  - 채팅 말풍선이 B에 뜨고 5초 뒤 사라진다.
  - 태그가 든 채팅·닉네임은 글자로만 보인다(DOM에 태그 없음).
  - 인원 "지금 2명"이 표시된다.
  - A가 숨겨지면 B에서 바로 사라진다.
  - A가 소식 없이 끊기면 30초 뒤 사라진다(가짜 시계).
  - 끊김 배지와 다시 연결이 동작한다.
  - 라이브러리 로드 실패에도 앱이 열린다.
- 보안: 실시간으로 나가는 모든 메시지(가짜 연결에서 기록)에 `profile.token` 문자열이 없다.
- 기존 테스트(SQL·단위 94·e2e 89)는 계속 통과해야 한다.
- 배포 후 실서버 확인:
  - 내장 브라우저 탭 두 개(서로 다른 프로필)로 진짜 Supabase에서 서로 보이는지 본다.
  - 공개 키로 접속되는지 본다.
  - 세민님과 친구 폰으로 최종 확인한다.

## 7. 완료 기준

- 두 폰이 동시에 들어가 서로 걷고, 건배하고, 말풍선 채팅하는 것이 보이고, "지금 2명"이 표시된다.
